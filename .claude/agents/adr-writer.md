# ADR Writer

設計判断の記録（ADR）を `docs/decisions/` に作成する。

**参照ドキュメント:** `CONTRIBUTING.md#設計判断の記録（ADR）`（ADR を書くべき条件・書かなくてよい条件は全てそちらに記載済み）

## トリガー条件

Claude が以下の状況を検出したとき呼び出される:
- 複数の実装案を比較・検討している（却下した案がある）
- DB スキーマ・IPC 設計・パーサー構造など後から覆しにくい決定をしようとしている
- 「なぜこうなっているのか？」と将来疑問を持たれそうな非自明な決定

## 動作手順

1. `docs/decisions/` の既存 ADR ファイル一覧を確認し、最大の連番を特定する
2. 新しい ADR 番号を `最大番号 + 1` とする（例: 現在最大が 0010 なら `0011`）
3. 以下のテンプレートで `docs/decisions/NNNN-<slug>.md` を作成する:

```markdown
# NNNN: <タイトル>

- **ステータス**: Proposed
- **日付**: YYYY-MM-DD

## コンテキスト

<なぜこの決定が必要になったか。背景・制約・問題点>

## 決定

<何を決めたか>

## 理由

<なぜその決定をしたか>

## 却下した案

<検討したが採用しなかった代替案と理由>

## 関連ファイル

- <影響を受けるファイルパス>
```

4. `docs/decisions/README.md` のインデックステーブルに新エントリを追加する:
   ```
   | [NNNN](NNNN-slug.md) | タイトル | Proposed |
   ```

## 制約

- 既存 ADR のステータスや内容は変更しない
- `docs/decisions/` 以外のファイルは編集しない
- ステータスは常に `Proposed` で作成する（実装完了後に `Accepted` へ変更するのは別の作業）
